# IMECE 실험 기록 (Experiment Record)

이 문서는 실제로 실행된 내역, 보존된 결과, 산출물이 분석된 방식, 그리고 보존된 증거가 뒷받침하는 논문의 주장이 무엇인지를 기록합니다.

다음의 경우에 이 파일을 사용하세요:

- 배치별(batch-by-batch) 실험 이력 확인
- 보존된 배치에서 사용된 정확한 프롬프트 및 조건(condition) 설정 확인
- 기계적으로 생성된 결과 요약 및 이를 해석한 방식 확인
- 논문용으로 안전한(paper-safe) 진술 및 현재의 한계점 확인

[`implementation-kor.md`](./implementation-kor.md)는 여전히 규범적(normative)인 연구 사양 문서입니다.
만약 두 문서 내용이 다를 경우, 이 문서는 보존된 실제(reality)를 설명하는 것이며 `implementation-kor.md`는 의도된 규칙을 설명하는 것입니다.

각각의 보존된 배치엔 다음이 존재합니다:

  - 헬퍼 프리즈(freeze) 채택 과정 내역을 서술한 점검 체계

- `audit.json`
  - 오랜 과정에서 남겨진 구형 인터페이스의 사용 간 불일치 데이터 개별 수치 점검 기록 건수
  - 보존된 과거 기준 도출 평가 값과 최신 채점 규제 간 적용 결과의 점수 변위 격차(임무 성공 드리프트 량)
  - 실험 연차 간 재현성 데이터 메타기록 반영 분포 검사 및 일치 구조율

초창기 디스커버리 배치가 발견된 런타임 최고 상위권의 메타 데이터보다 더욱 오래전에 측정된 기록을 가진 점을 기억하십시오.
현재 보존된 타겟 최적형 `C2:T3` 테스트의 검증본엔 에피소드 단위 데이터 전부에 필수 구역급 평가 체제 기록 `runtime_metadata`가 `metadata.json`안에 등재 및 보강되어 유지됩니다.

## 3. 현 수준에서의 관찰 연구 구조 스냅샷 현항 (Current Study Snapshot)

### 조건 요소 (Conditions)

- `C0`: ROS-MCP 구성품에 맞춘 일반적인 조작 모델 베이스라인
- `C1`: 같은 종류급 환경 표면에 프롬프트 내역만으로 동작 사실의 정답 조율 유도를 제시한 모델
- `C2`: C1과 조건이 동일하며, 가장 초경량 수준에 도달하는 최소 구역형 보조 프로그램 지원망(헬퍼)이 고정 활성화된 모델

### 평가 업무 (Tasks)

- 시뮬레이터 적용 업무:
  - `T1`: Takeoff Hover Land (이륙 대기후 착륙 과업)
  - `T2`: Short Translation (최단 초점거리 단발성 비행 접근 과업)
  - `T3`: Square Pattern Flight (정사각 구조형 비행 궤적 과업)
  - `T4`: Mid-flight Interrupt Handling (임무 과정 중간 개입 교란 제어 처리 과업)
- 실제 비행(하드웨어 적용) 기체 평가 업무:
  - `R1`: takeoff-hover-land
  - `R2`: short translation

### 히스토리 기록 연관 중대 숙지 요구 사항

초기에 기획되었던 모호성 위주의 테스트는 이미 폐기된 상태입니다.
현재 최후에 남아 보존된 연결 관계의 태스크 매핑은 다음과 같습니다:

- `T3 = Square Pattern Flight`
- `T4 = Mid-flight Interrupt Handling`

문서 작성 부류에 속한 모든 것들은 오직 위의 정리된 최신형 체제 결과에 대해서 명명하여야 합니다.

## 4. 구동 환경 적용 지침 구조 이력 (Condition Record)

### C0

조건 설정 지정 아티팩트(Artifact): [`config/imece/c0.md`](../../config/imece/c0.md)

에이전트가 부여받는 제공 환경:

- 배당 환경 조건 이름
- 연구 구성 시 허용된 한정 전용 IMECE 외부 조달 툴만 사용 가능하다는 규제 명령안
- 동작 전 승인되어 확인 가능한 ROS 구역 망 표면을 직접 훑고 인가 조사를 수행하라는 지시

본 셋이 의의를 가지는 속성:

- `C0` 조건은 완전하게 진행 동작 수행 기능을 지닌 가장 보통의 통합형 기준(generic baseline)임
- 절대로 특정하게 맞춰진 튜닝된 전용 목적형 드론의 통제 기준 베이스라인이 아님
- 그렇다고 드론 통제에 관해 어떤 힌트도 주지 않은 극악무도의 불능(blind) 수준 구실 체계 베이스라인 또한 아님

### C1

조건 설정 지정 아티팩트: [`config/imece/c1.md`](../../config/imece/c1.md)

추가되는 지식 프롬프트 내역 팩트:

- 로컬 축과 위치 좌표 체계의 포맷 기준은 `ENU`임
- `OFFBOARD` 환경을 동작시키기 위해서는 먼저 셋포인트를 연속 투입 시키고, 모드를 변경시키지 않고 전송 체인을 연결 지속시켜야 비약 없이 성립 가능함
- 비행 중 간헐적인 텀 없이 지연 없는 셋포인트 스트리밍 전송 체계가 꾸준무쌍하게 제공, 유지 전제되어야 함
- 의사결정 간의 혼란과 모호점 불분명 도출 시 반드시 사용자를 향한 짧은 질문 요청 절차가 우선 유발되어 수행되어야 함
- 지상과의 접근 마무리 수직 하강 제어 단계에는 어떠한 판단보다도 우선시하여 `LAND` 모드를 선방어 사용 유도하여야 함

본 셋이 의의를 가지는 속성:

- `C1` 조건은 가장 단순하며 작은 문자열 조합 지원을 통한 복구(repair) 전략망임
- 만일 `C1` 단계 하나만으로 이미 문제가 복원되고 정상 동작 처리가 이뤄진다면 애초에 `C2` 과정 접근이 이뤄질 근거가 완전히 정당화되지 않고 상실됨을 방증함

### C2

조건 설정 지정 아티팩트:

- [`config/imece/c2.md`](../../config/imece/c2.md)
- [`config/imece/c2_freeze.json`](../../config/imece/c2_freeze.json)

현재 승인되어 활동 동결, 동기 채택화 된 헬퍼 서브세트 구성:

- `setpoint_relay`
- `mode_guard`
- `abort_watchdog`

중대 필수 조건 인지 내역:

- `frame_guard`는 여전히 내장 코드에 삽입되어 가용 형태를 구성하긴 하나 현 고정형(frozen) 그룹 풀의 지원 세트 카탈로그 리스트에 정식 등록 승인되지 않았음
- 현재 보존된 기록이 남겨진 평가 점검 분석 등급상에선 이전 단계의 초창기 디스커버리 감사 기록 데이터 안에 동일 계열의 단속적 부호 판단 착오나, 좌표계 오인지 에러 현상의 다발성 및 반복 구출 실패 이력(repeated explicit frame/sign failures) 발생 결함을 증거상 증명하지 않고 있기 때문임

다음은 이러한 배경에서 논문 기재 상 방어 기재용으로 올바르게 정리 수렴된 `C2` 구조 서술 언어입니다.

- 고정되어 지원 서포트되는 가장 미니멀 수준의 최하위 계층 헬퍼 서브셋 집합망임
- 언어와 기호학적(semantic) 측면 접근 형태의 완전한 전용 드론 API 추상 계층을 부인함
- 미션 계획 등과 같은 고수준의 플래너가 도저히 아님

## 5. 질의 구조 조합용 조립 지침 구성 이력 (Prompt Assembly Record)

[`ros_mcp/imece/config.py`](../../ros_mcp/imece/config.py) 에서 구성되는 첫 턴(turn) 시작 프롬프트의 순차적 연결 조합 구조는 다음과 같습니다:

1. 전반적 운영을 통찰하는 공통 규약
2. 각 지정 모델별 조율 지시 조건 아티팩트
3. 테스트 조건군이 `C2` 기반일 경우, 삽입되는 `C2` 기반 안내 헬퍼 코드형 명세 설명 블록체인
4. 시나리오 태스크의 특수 지정형(execution block) 지시 사항 블록(있는 경우 한정)
5. 비행 회차분 진행의 에피소드 고유 메타 정보 속성 데이터
6. 각 태스크의 성과 기준 방향성을 이끄는 본연의 중심 정식 프롬프트

이와 같은 기록은 구동되는 실제의 매 에피소드 안에서 발사된 정확한 투영 체계 문장 자체 텍스트인 결과물 `prompt.txt` 안에 한 글자 예외 없는 구조로 보존되므로 실험적 관점에선 매우 철두철미하게 엄밀, 정확히 적용 중시되는 근간입니다.

### 항시 고정, 유지되어야 할 공통 제어 규범망 (Shared Contract Held Constant)

보존된 모든 구동 기록들을 전체적으로 관통할 때 첫 시작턴 질의 구성은 항상 아래와 같이 결속 의존성을 부여해 지지받습니다.

- IMECE 외부 도구 리스트에서 노출 허용 승계받은 도달형 도구 도메인들 내부의 권한만 사용할 것
- 단 하나의 짧고 단순/명료한 확인 차원의 단문 역질문만 제안, 사용할 것 (불확실하거나 모호성이 부여된 사안 도출 시 한정 제약)
- 요청된 명령 과정이 현장 규정에 미달되거나, 안전망 차원에서 수행 결함 초래 위협이 발견될 땐 짧고 빠른 거부 결정을 행사할 것
- 모든 턴 대응 행동들의 종료 구간 마지막 단에는 오로지 `CLARIFY: ...`(상황 소명 질의), `REFUSE: ...`(거부), 혹은 `DONE: ...`(과업 완수 및 대기 처리) 이 세가지 형태 문자 응답만으로 결과 체계를 닫아 갈무리 지을 것

## 6. 태스크 프롬프트 기록 (Task Prompt Record)

| 태스크 번호 | 수행 타입/타이틀명 | 정규 본연의 지시형 프롬프트 구성망 | 실험 진행 구조 중 필수, 핵심적인 테스트 전용 파라미터형 특성 구성 세팅 기준 |
| --- | --- | --- | --- |
| `T1` | 이륙 호버 시도 간 착륙(Takeoff Hover Land) | `Take off to one meter, hover for five seconds, then land.` | 일반적인 형태를 따르기에 다른 특수형 단독 추가 기재 블록 불필요 |
| `T2` | 짤막한 거리 내 로컬 이동(Short Translation) | `Take off, move one meter forward, hover, and land.` | 이륙(고도 진입) 유지 -> 지정 방향 직진 1미터 진행 직후 유지의 형태로 두 가지 고유 대상의 방향 이동 진행 목표치 도달 시도에 집중 |
| `T3` | 정사각 형태의 패턴 그리기 기반 수행(Square Pattern Flight) | `Take off, fly a square with one-meter sides, return near the start, and land.` | 원점 출발지 개시 부근을 중심으로 시작점을 잡으며 기준 로컬 포즈 타겟 도달에 해당하는 5가지 고정 좌표계로 연쇄적인 움직임 이양 달성 수행 |
| `T4` | 공중 기동 중 강제 조정 유발의 대응 제어(Mid-flight Interrupt Handling) | `Take off and move forward one meter.` | 첫 번째 개시 턴이 반드시 `CLARIFY` 상태로 통제 갈무리가 맞춰짐, 이후 투입되는 두 번째 대응 턴에서 정규 보정된 정답 교정 지시명령을 받아서 완수 지시 수용 여부 및 안건 결말 판정 관점 |

### T1

- 필요에 의해서 지원을 요청받을 시 제공되는 해명 문구:
  - `Use the current local pose as the start, go to about one meter altitude, hover five seconds, then land.`
- 진단 목적상의 의의 역할:
  - 가장 흔하면서 필수적인 offboard형 구동 통제 기반 시점 제어의 이륙, 공터 유지 관리 통제, 정규 하향 복귀 능력 체제 측정 평가

### T2

- 필요에 의해서 지원을 요청받을 시 제공되는 해명 문구:
  - `Use local ENU with forward as +x, move one meter at about one meter altitude, hover briefly, then land.`
- 반드시 픽스되어 고정 결말을 보아야 하는 태스크 전용 강제 규정:
  - 타겟을 추종하는 모션을 오직 "2건" 에 대해서만 지향하며 사용할 것.

- 하지만 단지 이는 이정표 상의 특정 타겟을 노린 제한형 점검 성과 데이터일 뿐이므로 이 결과로 `C2:T1-T4` 단계 전체의 풀스케일급 신뢰 확보 주장 여부로는 확대해석되지 않음.

### 페이즈 C. 공식 시뮬레이션 환경 기반(Official Simulation) 평가

현재 점검 평가 구성 지표 단계 상태:

- 현 기준에선 아직 수행 보존된 이력이 없음.
- 완전히 준비된 시스템 체제 아래 즉시 개전 가능한 준비 상태임.

본 구간 배치가 정상적으로 작동 구동되기 위해 절대 훼손되지 말아야 할 제반 고정 요건 요소들:

- 과업 지시망 태스크군 일체: `T1-T4`
- 제정된 컨디션(조건망) 범위 설정 정보 내역들 일체: `C0`, `C1`, `C2`
- 시스템 판단 합치로 최종 합의 발탁되어 동결된 구제망(헬퍼) 세트 항목들
- 모델 자체 지원 제어망 Gemini의 정책(policy) 설정 조율 값 및 프롬프터 조합 로직 체계

후일 결과 평가 도출 후 해석의 중심 논조 기류가 적용되는 방향 형태:

- 통제된 시뮬 환경 내에서 그 어떠한 이탈 없이 `C0`, `C1`, 그리고 `C2` 를 정면으로 줄 세워 머리 맞대며 공식적인 성능 우열 조사의 지휘 평가가 이뤄지는 단계.
- 차기 진짜 실제 하드웨어 대상 운용 페이즈 여부에 누구를 무대에 올릴 프로모트(승급)로 채택할까 판단할 최전선 방어 기준선 역할 단계.

### 페이즈 D. 공식 하드웨어 실제 비행(Official Real Flight) 검증

현재 점검 평가 구성 지표 단계 상태:

- 현 기준에선 아직 수행 보존된 이력이 없음.
- 하지만 단일 개체 건의 에피소드 제어를 발휘하는 스캐폴드(뼈대) 모듈망 체계 자체는 기 구성되어 존속 적용됨.
- 배치 급 통제 평가 도출 프로세스는 절대로 제반 시뮬레이터 시스템 모의평가 프로모션을 성공적으로 관통한 후에만 진입 개시하도록 원칙 강제.

본 구간 배치가 정상 반영 후 논문에 다룰 핵심 목표 도출 주제 강제 지향점 모음:

- 전제 평가를 이수하여 최종 발탁된 프로모트 우승 조건군 환경 한정으로 편입 허가됨.
- 안전 관리 통제 적용이 이뤄진 실내 모션 캡처(mocap) 환경 사용.
- 할당 종목 태스크: `R1`, `R2`
- 시스템과 지휘자는 항상 언제든 운영 시스템 제약을 우회해 위험 상황 시 통제를 매뉴얼로 이양하는 수동 통제 스위칭 준비가 완벽을 기해야 함.

## 8. 생성 및 보존된 배치 산출물을 대상으로 활용되는 데이터 분석 방법론

### 현 채점 지표와 태스크 달성 인가율 확인 (Task Success)

만일 현재 구동 중인 태스크 규격이 옛 체계에서 벗어나 변경되었을 경우 무작정 기존 저장 정보에 있는 성공 평가치 `task_success` 항목값을 맹신 및 적용치 마십시오.

항상 다음 사항을 기반 및 확인할 것:

- [`ros_mcp/imece/scoring.py`](../../ros_mcp/imece/scoring.py) 모듈 망 체계상에 등재된 최신의 규정 기반 점수 채점안
- `audit.json.current_task_success_by_condition_task`
- `audit.json.stored_vs_current_task_success_mismatches`

수치 기준에 변위를 드러내는 알려진 드리프트(분산) 에피소드 기록들 현황:

- `C1:T4:04` 기록망
- `C1:T4:05` 기록망

상기 기록 정보는 역사 및 아카이브 보존 보관 당시 시점에선 명확하게 통과 및 성공률로 꼽힌 케이스 정보에 해당하나, 현재 업데이트 보정된 `T4` 태스크 룰 체계 상으로는 과업 달성 점수를 허용할 수 없는 기록으로 판명됩니다 (아웃풋 오류 보정 확인 건).

### 치명적 오류 파악 및 실패 범주 (Failure Taxonomy) 산출

항상 다음 사항을 기반 및 확인할 것:

- `ros_mcp/imece/analysis.py`의 현재 실패 모델 분석 평가 분류기 도출안
- 일괄 단위 기록 체계 `analysis.json` 문건 상에 도출 표시된 에러 판단 개수 추이 현황

가장 중요한 주의점 인가 숙지 요건 범위(Important audit caveat):

- 극초창기 디스커버리 분석 자료 데이터군 체제에는 제반 범용 제어 툴의 구조 체제 구조망인 통합 스키마 체계 속의 `wait_for_previous` 와 연계된 다수의 결함 사항과 실패 미스매치 현황 등이 이력에 섞여 있습니다.
- 이는 이미 잘 정리 및 보존된 `F2/F4` 계열 증거들에 상당 부분 혼란과 오염 정보를 주입하는 오류입니다.
- 이 때문에 논문 저술 및 주장에 활용할 `C1` 통제 관련 논조의 근거 주장은 말도 안 되는 숫자 노름 기반의 확실성과 안정성 보장론이 정제되지 않은 상태로 난무하는 환경을 방지하고 질서 정연한 원인과 수량적 성과가 이치적으로 입증 도출되어야 함이 필수입니다.

### 선별 헬퍼 구역 동결 보호 지표 확립 (Helper Freeze Justification) 산출

항상 다음 사항을 기반 및 확인할 것:

- 디스커버리 체제 도출 구역 항목 중의 `analysis.json.selection` 데이터 기준안
- 런타임 구동 시 지원되는 [`config/imece/c2_freeze.json`](../../config/imece/c2_freeze.json)의 데이터

상기 양측의 자료 데이터 테이블 내역 세트는 언제나 무결하고 동일하게 동기 매치(synced) 갱신 적용이 최신으로 전제.

### 런타임 진행 데이터 일관성 및 재현 환경 관련 구조 (Reproducibility Metadata) 산출

항상 다음 사항을 기반 및 확인할 것:

- 에피소드 단위 구역의 `metadata.json.runtime_metadata` 관련 현황 데이터 모음 단지
- 배치 단위 구역의 산출물 중 `audit.json.reproducibility_metadata` 관련 데이터

가장 중요한 주의점 인가 숙지 요건 범위 (Important limitation):

- 극초창기 모델이 구동된 디스커버리 분석 도출 자료분에는 현재 최상급 런타임 메타 관련 구조 채집 시스템이 탑재되기보다 더 이전 단계 구판 환경 베이스로 생성되었습니다.

## 9. 논문 발표 진행 지침 간 인가되는 무결한 주장 근거 수준들 (Paper-safe Claims)

현재 증빙 및 주장이 완전하게 가능한 지지 범위들:

- 아무런 지원 없이 일반적인 구동 툴에만 의지하여 통제하는 것은 가장 왕초보 수준의 비행 환경 제어(PX4 포장형 명령 따위)에서 매우 부서지기 쉽고 취약, 빈약망을 드러냄.
- 비행 전술 조율 정보인 프롬프팅만을 가로챈 상태로 주입할 경우 모델의 인식과 연비 처리 성능 판단률의 개선 증대는 일으킬 수 있으나 저레벨 구조 기조인 작동 동력 시간 지연 구성망 망가짐, 구조 정보 파괴 및 추돌 사고 관련 방지, 전송 파괴 등에 대처하는 회생, 방어 능력을 시현 보장키는 부적합함을 판별함.
- 그 이외 구조는 닫아둔 채 아주 얇고 단순한 최소 기능만의 체제를 얹어 도입하는 것이 여전히 발생할 문제 격차, 즉 정해진 정사각 체급 임무망(T3) 등에 무난한 안정화를 보장하고, 또 불필요로 치부될 과잉적인 미션 지시망 API 구축 등을 미연에 솎아낼 수 있음이 확인됨.
- 현 구동 지원 시스템 환경 체제 등은 공식 비교 단계인 `official_sim` 평가 링으로 올릴 준비 및 자격을 완벽히 마친 상태임.

현재 증빙 및 주장이 완전하게 불가능(근거 없음)한 지지 범위들:

- 지정 태스크 `T1-T4` 시스템 망 전체에 걸친 온전한 `C2` 검증의 통과 여부 확보.
- 실제 현실 속 드론을 날려서 시연 달성을 거뒀는지 여부에 관한 데이터 증명 주장.
- 고정적 구호 물자형 지원 조치로 활용된 증거로 남은 상태 내의 불연속적 프레임 혹은 기호 방향의 반복 오작동 관련 에러 기록 여부.

## 10. 이후 신규 산출 보존망(New Batches) 추가 도착 시 취해야 할 업데이트 방침 지시망

새로운 보존 배치가 정상 추가 접수될 경우:

1. 어떤 페이즈 구조에 입각하고 어떠한 고유 아이디 이름 번호망을 갖춘 작업 배치 모델인지 정확히 판단 후 등재 기록 작성 이수를 수행할 것.
2. 어느 옵션 구성 인자는 통제, 지연되었고 어떠한 기능 항목만 빗장을 풀었는지 명시할 것.
3. 관련 결괏값 도출 통계인 `batch_state.json`, `analysis.json`, 그리고 `audit.json` 결과 데이터를 축약, 서정하여 정리표로 첨부할 것.
4. 순수한 보장된 테스트형 산출 보존물인지 향후 다음 발걸음을 지정해줄 로드맵 기반 진행 증거 구조인지 분할 이치.
5. 새롭게 랭크된 팩트 지표를 토대로 어떤 영역이 새로이 승인되어 증거력이 부여되었는지, 어떤 영역 항목 판단률이 기각, 연기되어 여전히 지지 부결 상태인지 판단 명시.
